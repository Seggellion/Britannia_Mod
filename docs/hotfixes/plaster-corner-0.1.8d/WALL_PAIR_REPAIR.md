## Cause and correction

The mismatch predates the plaster mesh repair. Actual decoration wrote only the hit state. The lower model renders both vertical sections while the upper renders air, but the upper stored state drove an independent collider. Actual old-candidate probes established a 0.5625-block branch displacement, not merely a harmless property discrepancy. Mirror transformations flipped both BRANCH_RIGHT and MIRRORED, undoing physical branch reflection; subsequent generic orientation normalization could also replace a one-post corner with a two-post variant.

`DoubleWallBlock.decoratePair` now resolves either hit through a validated same-ID LOWER/UPPER pair. Lower is the visual authority for legacy recovery. Both states are written with neighbor-shape notifications suppressed, checked, and rolled back on incomplete writes; ordinary notifications follow the complete pair. Main-hand rotation and offhand mirroring use the actual item path. Broken/wrong-ID pairs fail without fabricating or mutating a counterpart. Non-mirrorable offhand walls remain unhandled; spectator edits are unhandled.

Upper collision/outline reads a matching lower owner's geometry while retaining the queried HALF. Queries do not rewrite saves. A later ordinary shape update touching that half synchronizes from the lower; a successful decorator operation resolves the full stored pair. No global scan, startup migration, production-world rewrite or removal of legal saved selectors is introduced. Existing mismatches may therefore remain stored until an appropriate notification/edit, but their upper collision follows the visible lower immediately.

Registered-state testing exposed vanilla's static collision cache: it builds shapes in an empty world, so a context-dependent upper lookup alone is insufficient. DoubleWallBlock now requests dynamic shapes. This adds one same-column lower lookup for an upper shape query; valid synchronized pairs retain their previous geometry. Sandstone window and battlement overrides use the same lower canonicalization while keeping their separate lower/upper openings/slopes.

Physical wall-run conversion accounts for `BRANCH_RIGHT XOR MIRRORED` on asymmetric corners/junctions. Generic WallConnection's algorithm, bannister and floor-support derivation are unchanged. A mirrorable corner has two equivalent choices of main arm; derivation selects the representation that preserves its authored branch variant, preventing one-post/two-post swaps during rigid transforms while joining the same physical edges. New straight-to-corner placement retains ordinary derivation. For a decorated connected corner, normalization can choose the other main arm rather than moving the joined slabs; an isolated forced corner can normalize to straight. Forced state render checks must still be distinguished from normal placement and notification behavior.

World mirror reflects FACING and toggles MIRRORED once, preserving the authored BRANCH_RIGHT selector. Rotation preserves that selector and mirror. No registry IDs, property definitions, blockstate selectors, model meshes, textures, collision dimensions or version changed in this continuation. The prior repaired assets and scoped half generator remain intact.
